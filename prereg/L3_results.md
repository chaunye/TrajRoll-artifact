## 2. H4 自检门：3 条 FAIL = 判据侧，实现无 bug（证据如下）

原判据是为 **4B 批**写的，其隐含前提「b0 是个从不做成的失败者、各臂路径同长」在 8B 上整体失效。三条逐条核完，**全部是前提塌陷，不是实现问题**；按 A1A2 先例（第 3 条 FAIL → 判据写错 → 立 3′）立 3′ 替代判据，**本判定属事后改判，此处与补充材料都如实披露**。

### 2.1 判据 1「足迹严格单调 b0 > t16 > t8 > t4」→ FAIL（731 > 753 > 733 > 600）

| | 4B 批（前提成立） | 8B 批（前提塌陷） |
|---|---|---|
| b0 行为 | 1/20 成功，19 次跑满 20 轮，Σturns=391，带 padding 的失败正文不断堆积 → foot **2443** 高高在上 | **20/20 成功，7–9 轮收官**，Σturns=158，每 run 仅 ~1 次带 padding 的失败 → foot **731** |
| t16 是否真的裁剪 | 真裁（b0 终值 msgs 23–42，t16 封顶 19–20） | **13/20 个 run 从未触发裁剪**（终值 msgs 分布 {15:4, 17:9, 19:7}，floor=2+16=18）→ t16 结构上≈b0 |
| 结果 | 2443 > 1525 > 901 > 745 ✓ | b0 与 t16 只差 ±3%，是轨迹噪声 + t16 平均多 1 轮（163 vs 158） |

**机制层证据（日志实读）**：`ab_truncate_n4_s1.log` 的 msgs 列严格按 `HEAD_KEEP=2` + 窗口 n 演化（触发裁剪的轮印 6，reject 轮印 8，终值 8 = 6+2），与 `slide_window` 代码逐位一致；t4 20/20 触发裁剪、t8 20/20 触发（终值 11 = 10 + answer 1）。裁剪实现**无问题**。

**3′ 替代**：`foot(t4) < foot(b0)`（聚合 600 < 731；逐 seed 16/20）+ `foot(ours) < foot(所有 truncate 臂)`（逐 seed 20/20、20/20）。原判据中「b0 必须是上界」的子句废止，理由如上（b0 不再膨胀、t16 在本批基本不裁）。
**诚实注记**：truncate 三臂内部的 n 单调性**只在聚合层成立**（600 < 733 < 753），逐 seed 仅 9/20 —— 因为 t16 基本不裁剪，它与 t8 的差是轨迹噪声，不是窗口效应。这条本身就不强，照实写。

### 2.2 判据 2「foot(label) ≥ foot(b0)」→ FAIL（726 vs 731，−0.7%）

- **同轮数配对（13/20 个 seed 两臂轮数相同）：`integral(label) ≥ integral(b0)` = 13/13 ✓**
- 轮数不同的 7 个 seed 里，**6 个是 label 先做完**（label Σturns 153 < b0 158）→ 聚合均值在比两个**长度不同**的样本，−0.7% 是轮数分布拽出来的
- 机制层证据：`ab_label_s1.log` 与 `ab_b0_s1.log` 轨迹逐轮相同，第 6 轮 prompt **1365（label） vs 1326（b0）**，差 39 token = 墓碑那一行 —— **墓碑是严格加性的**，轨迹内 label ≥ b0 恒成立

**3′ 替代**：同轮数 seed 上 `integral(label) ≥ integral(b0)` → **13/13 PASS**。

### 2.3 判据 4「Σintegral(rollback) < Σintegral(b0)」→ FAIL（186 316 vs 115 490）

- 前提 = 两臂轮数相当。4B：rollback 400 轮 vs b0 391 轮 → 115k < 955k ✓（8.3×）
- 8B：**rollback 跑满 400 轮（0/20，锁死）vs b0 只用 158 轮（20/20，收官）** → 这个和式比的其实是「谁做的轮数多」，前提没了
- **机制层证据（决定性）**：`ab_rollback_s1.log` 第 5 轮起 **msgs 恒为 10、prompt_tokens 恒为 505**、每轮重发同一个 `read_file data/profile.json`（dup=15）—— 这正是 A1A2 附录 3′ 要的运行时证据（`prompt_tokens 恒定 + msgs 恒定`），**在 8B 上逐字节复现**。终值 10 = 2（init）+ 2×(3 次成功 + 1 次 reject)，可由代码直接推出；我原先照抄的「恒为 4」是 4B 的数（4B 只有 1 次非失败轮）
- 协议错误率同构：rollback tools_fail 80% / dup 75%（4B：95% / 90%），锁死签名一致

**3′ 替代**：改用逐轮量 `foot(rollback) < foot(b0)` → 466 < 731，**逐 seed 20/20 PASS**；运行时证据 `msgs`/`prompt_tokens` 恒定 → PASS。

## 3. H1–H3 判定（门过后才看）

## 6. 结论怎么写（给论文与处置记录的定稿口径）

> 我们在第二个模型（Qwen3-8B）上重跑了同一批七臂实验（N=20，判据跑前冻结）。
> **效率结构复现**：保留+墓碑相对全量保留把每轮上下文足迹从 731 降到 448 token（1.63×），截断基线的每轮重算量是它的 2.47×（4B 上对应数字为 3.7× 与 5.3×）。
> **正确率结构不复现**：Qwen3-8B 在该任务族上已饱和（b0 = ours = 20/20，Fisher p = 1.0），因此正确率维度的机制收益**只在 Qwen3-4B 上可测**（11/20 vs 1/20，p = 0.0012）。
> 负对照「丢弃无墓碑」在**两个模型上都锁死**（4B 与 8B 均 0/20），说明锁死由上下文操作决定、与模型强弱无关。
> 「截断 4 条」**只在本批锁死**（8B 0/20；4B 为 8/20 = 40%，滑窗非单调、4B 锁死的那档是 t8）—— **两批不互比**，
> 「两条负对照在两个模型上都锁死」的说法**不成立**，只对「丢弃无墓碑」成立。
> 我们据此把机制的适用范围限定为「弱模型区间提正确率、所有区间省上下文」，并把任务族对强模型饱和列为本工作的局限。
